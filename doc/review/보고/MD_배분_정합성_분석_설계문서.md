## 1. 분석 배경 및 목적

### 1.2 분석 대상

- **브랜드**: Discovery 의류 (BRAND_CD = 'X')
- **기간**: W1(2026-04-27~05-03) / W2(05-04~05-10) / W3(05-11~05-17), 총 3주
- **데이터**:
  - MD 보충배분 CSV → `md_alloc.json` (week, style, store) → 배분수량
  - Snowflake `FNF.SERP.BIM_SHOP_DD_STK` → 매장별 일별 판매 데이터

## 3. 현재 로직의 근본적 한계

### 3.1 핵심 문제: 재고를 고려하지 않은 직접 상관 비교

**현재 로직의 암묵적 가정**:
> "잘 팔리는 매장에 많이 배분했으면 MD가 잘 한 것"

**실제 MD 결정의 올바른 기준**:
> "잘 팔리는데 **재고가 부족한** 매장에 많이 배분했으면 MD가 잘 한 것"

**반례**:
```
A매장: 판매속도=10개/주, 현재재고=11개 → 커버리지 1.1주 → 배분 급하지 않음
B매장: 판매속도=5개/주,  현재재고=2개  → 커버리지 0.4주 → 배분 시급
→ 올바른 MD = B매장에 더 배분
→ 현재 로직 = A매장 velocity 높으니 A 우선이라 오판
```

### 3.2 세부 로직 문제들

#### ① both_set 이중 정의 혼용
- 헤드라인은 `active_md = 33쌍` (vel>0 필터 적용)
- 상관계수 산점도는 `both_set = 78쌍` (vel 데이터 존재 여부만으로 판단, vel=0도 포함)
- 두 기준이 혼용되어 일관성 없음

#### ② vel>0 활성 기준 임계값 없음
- 3주에 1개 판 매장과 주당 10개 파는 매장이 동일한 "판매활성"으로 분류됨
- 최소 임계값(예: 주간 vel ≥ 0.5개 이상) 정의 필요

#### ③ 주차-속도 창 정합성 미검증
- `active_only` 판정 시 주차 구분 없이 "3주 중 하나라도 vel>0" 기준 사용
- W1 배분은 vel_w1만으로, W2는 vel_w2만으로 비교해야 함

#### ④ 공급 제약 미반영
- 창고에 스타일별 가용재고가 얼마나 있었는지 없음
- "MD가 안 보냈다" vs "보낼 재고가 물리적으로 없었다" 구분 불가
- 873개 missed pair 전부에 배분할 재고가 없었을 수도 있음

#### ⑤ 스타일 코드 끝 3자리를 시즌 코드로 오해
- 063, 056, 053, 054 등 스타일코드 끝 3자리를 시즌 그룹으로 임의 사용
- 이는 공식 시즌 코드 체계가 아님 (확인 필요)
- 실제 시즌 코드 체계를 확인하여 재분류 필요

## 4. 올바른 평가 지표: Need Score

### 4.1 개념

```
Need(매장, 스타일) = 목표 커버리지 주수 × 판매속도 - 배분 직전 재고

Need > 0  : 재고가 부족한 상태 → 배분 필요
Need ≤ 0  : 이미 충분한 재고 → 배분 불필요
```

### 4.2 평가 방법

```
Spearman( MD 배분량 , Need Score )
```

- MD가 Need가 높은 매장·스타일에 많이 배분했는가?
- 현재 `Spearman(MD 배분, velocity) = 0.12` 는 틀린 기준
- **올바른 기준**: `Spearman(MD 배분, Need Score)` 

### 4.3 목표 커버리지 주수(target_weeks) 설정 문제

- target_weeks를 얼마로 할 것인가?
- 보충배분 사이클(리드타임)과 연동해야 함
- 예: 다음 배분까지 2주라면 target = 2주치 재고 유지가 목표
- **→ 미결 사항: 실제 배분 주기 및 리드타임 확인 필요**

## 5. 재고 데이터 확보 방향 — Snowflake 탐색 결과

### 5.1 갈래 A — BIM_SHOP_STK 직접 조회 (❌ 사용 불가)

**테이블**: `FNF.SERP.BIM_SHOP_STK`

**구조**:
- STK_QTY(재고수량) 직접 제공
- FST_GI_DE, FST_SALE_DE, LST_SALE_DE 등 날짜 메타 필드 있음
- **STD_DE(날짜 차원) 없음** — 시점별 재고 조회 불가
- SSN_CD 형식이 '21S', '23F' 등으로 다름

**결론**: 배분 직전(2026-04-26) 시점 재고 복원이 구조적으로 불가능. **사용 불가**.

### 5.2 갈래 B — BIM_SHOP_DD_STK 누적 역산 (⚠️ 제한적 사용)

**테이블**: `FNF.SERP.BIM_SHOP_DD_STK`

**구조**: STD_DE 일별 차원 + NOR_GI_QTY(입고), NOR_SALE_QTY(판매), RTN_SALE_QTY(반품) 등

**실험 결과**:
```sql
-- DMSP71063 × 10003~50057 샘플
-- STD_DE <= '2026-04-26' 기준 누적
est_stock = SUM(NOR_GI_QTY) - SUM(NOR_SALE_QTY) + SUM(RTN_SALE_QTY)
-- 결과: 25~33개 (물리적으로 납득 가능한 수치)
```

**그러나 사용하지 않기로 결정** (사용자 지시):

> ⚠️ `BIM_SHOP_DD_STK`의 NOR_GI_QTY(입고)는 **MD의 보충배분 외에 자동 처리분, 판매분 조정 등 노이즈가 포함**되어 있어 MD 배분량 데이터로 사용 불가.  
> MD 보충배분 데이터는 **CSV 파일(`md_alloc.json`)만을 유일한 출처**로 사용한다.

**BIM_SHOP_DD_STK 사용 범위**:
- ✅ **판매 데이터만 사용**: `NOR_SALE_QTY`, `RTN_SALE_QTY` → velocity 계산
- ❌ **입고/출고/조정 컬럼 사용 금지**: `NOR_GI_QTY`, `NOR_ADJ_GI_QTY`, `RTN_GI_QTY` 등

### 5.3 재고 데이터 미확보 상태에서의 대안 검토

현재 배분 직전 매장 재고를 신뢰할 수 있는 방식으로 가져올 수 없는 상태.  
아래 대안 중 하나를 선택하거나 추가 데이터 소스를 확인해야 한다.

**대안 1: 다른 Snowflake 테이블 탐색**
- SERP 스키마 내 다른 재고 스냅샷 테이블이 있는지 확인 필요
- 예: 주차별 재고 스냅샷 테이블, BIM_SHOP_WK_STK 형태의 테이블

**대안 2: MD 내부 시스템 데이터 활용**
- MD가 배분 의사결정 시 실제로 참고하는 재고 화면의 데이터 소스 확인
- 해당 소스에서 직접 추출 가능한지 확인

**대안 3: 재고 없이 분석 구조 변경**
- Need Score 대신, **커버리지 일수** 개념을 velocity만으로 근사
  - 단, 이 경우 배분 이전 재고를 0으로 가정하는 bias 존재
- 또는 **배분 이후 판매 추이**를 통해 역으로 배분 품질을 평가
  - 배분 받은 매장의 이후 3주 판매 vs. 배분 못 받은 매장의 이후 3주 판매 비교

**대안 4: 창고 재고 데이터 활용**
- 창고(90019)에서 매장으로 나간 이동 이력이 별도 테이블에 있을 수 있음
- WMS(창고관리시스템) 연동 테이블 탐색 필요

## 7. AIA vs. MD 비교 분석 설계 (후속 작업)

### 7.1 분석 목표

> MD가 배분한 결과와 AIA가 배분했을 경우를 비교하여 AIA의 개선 효과를 수치화

### 7.2 설계 옵션

**옵션 A — 예측값 vs. 실판매 상관관계 비교 (권장)**

```
Spearman(AIA 예측값, 판매속도) vs. Spearman(MD 배분량, 판매속도)
```

- AIA 예측 테이블: `ML_DIST.PRED_SC_W` (LightGBM) 또는 `ML_DIST.PRED_SH_SCS_W` (TSB)
- 동일 주차·매장·스타일의 예측값을 pull해서 velocity와 Spearman 비교
- 현재 MD Spearman = 0.12 → AIA가 높으면 "더 나은 우선순위 판단" 근거
- **필요 데이터**: PRED_SC_W에서 W1~W3 주차의 예측값

**옵션 B — AIA 시뮬레이션 배분**

- AIA의 배분 우선순위 로직을 재현해 "AIA가 배분했다면?" 결과 생성
- 같은 가용재고 제약 + AIA 스코어 → 시뮬레이션 배분 생성
- 873개 missed pair 중 AIA가 몇 개를 커버했는가 직접 계산
- **필요**: AIA의 스코어링 로직 (변수, 가중치), 창고 가용재고 스냅샷

### 7.3 선결 조건

- [ ] AIA의 배분 우선순위 결정 방식 확인 (예측값만 쓰는지, 재고 커버리지 함께 쓰는지)
- [ ] PRED_SC_W 테이블 접근 권한 및 데이터 형식 확인
- [ ] 창고(90019) 가용재고 데이터 확보 가능 여부

## 11. 핵심 전제 및 분석 원칙

1. **MD 보충배분 데이터는 CSV만**: BIM_SHOP_DD_STK의 GI(입고) 컬럼에는 보충배분 외 자동처리분이 포함되어 노이즈 존재. 오직 제공된 CSV만 사용.

2. **BIM_SHOP_DD_STK 사용 범위**: 판매 컬럼(NOR_SALE_QTY, RTN_SALE_QTY)만 사용. 입고·출고·조정 컬럼 사용 금지.

3. **단일 주차 데이터로 모델 평가 금지**: 최소 2주 이상, 구간별 편향 분리 분석 필수. 1주차 결과만으로 결론 내리지 않는다.

4. **상관계수는 Spearman 우선**: 배분량·판매량 모두 극단값이 있는 skewed 분포. Pearson보다 Spearman이 더 적합.

5. **공급 제약 항상 명시**: 기회손실(873개 missed pair) 언급 시, 창고 재고 제약으로 물리적으로 배분 불가였을 수 있음을 항상 단서로 달 것.

6. **운영 제약 반영**: 월-금만 배분 실행. 창고도 주말 미운영. 리드타임 계산 시 주말 제외.
