## 1. 프로젝트 목적

### 1.1 현재의 문제

F&F의 보충배분은 현재 유통 MD가 매주 수기 엑셀로 집행하고 있다. MD가 판매 데이터를 직접 조회하고, 경험과 직관을 바탕으로 매장별·사이즈별 수량을 입력해 S-ERP에 업로드하는 방식이다. 이 방식은 세 가지 구조적 한계를 가진다.

**① MD 개인 역량 의존**
담당자가 바뀌거나 브랜드·SKU 수가 늘어날수록 배분 품질이 불안정해진다. 동일한 상황에서도 MD의 경험치와 판단 기준에 따라 결과가 달라지며, 이 기준이 조직 내에 명시적으로 문서화되어 있지 않다.

**② 베스트셀러 대응 구조적 취약**
잘 팔리는 SC(스타일-컬러)일수록 재고가 빠르게 소진된다. 수기 배분 기준으로는 판매 속도를 선제적으로 반영해 물량을 집중시키기 어렵고, 결과적으로 판매 기회 손실이 발생한다.

**③ 반복 작업 공수 과다**
스타일 수×매장 수×사이즈 수의 조합을 매주 반복적으로 계산하는 작업 자체가 비효율적이다. 단순 기준의 반복 판단을 MD가 직접 수행하고 있어, 고부가가치 의사결정에 투입할 수 있는 시간이 줄어든다.

### 1.2 프로젝트 목적

> **"AI 기반 수요 예측 + 정수 최적화(ILP)로 보충배분 의사결정을 자동화하여, MD의 판단은 예외 처리와 최종 확인에 집중할 수 있는 구조를 만든다."**

구체적인 목표는 두 가지다.

- **베스트셀러 재고 부족 방지**: 주간 판매 예측치를 기반으로 잘 팔리는 SC에 선제적으로 물량을 집중 배분
- **MD 배분 의사결정 효율화**: 시스템이 최적 배분 수량을 제안하고, MD가 검토·조정·확정하는 구조로 전환

### 1.3 적용 범위 (브랜드)

초기 적용 대상은 MLB(M 브랜드)로 시작하며, 이후 Discovery(X), MK, Duvetica(V), Sergio Tacchini(ST) 순으로 확장한다. 운영 단위는 **배분그룹(shopGrpNo)** — 브랜드별로 구성된 매장 묶음 단위로 배분이 실행된다.

## 2. 솔루션 접근 방식

### 2.1 전체 흐름

```
Snowflake (판매 이력 · 마스터)
        │
        ▼
① 수요 예측 모델 (ML)          ← Colly 담당
   SC-Total (LightGBM / TFT)
   SC-Shop (TSB)
        │
        ▼
② 정수 최적화 서버 (ILP)        ← Colly 담당
   POST /optimize
        │
        ▼
③ 유통MD 화면 (Next.js)        ← 하민 담당
   매장 조정 → 배분 시뮬레이션 → 엑셀 다운로드 → S-ERP 업로드
```

### 2.2 ① 수요 예측 모델링 (Colly 담당)

Snowflake에 적재된 ML 예측 결과(`FNF.ML_DIST`)를 화면에서 소비한다. 두 단계의 예측 모델이 존재한다.

| 모델 | 테이블 | 예측 단위 | 알고리즘 | 의미 |
|---|---|---|---|---|
| SC-Total | `PRED_SC_W` | 스타일-컬러 × 주간 | LightGBM / TFT | "이번 주 이 SC는 전 매장 합쳐 몇 개 팔릴 것인가" (절대 수량) |
| SC-Shop | `PRED_SH_SCS_W` | 스타일-컬러-사이즈 × 매장 × 주간 | TSB | "총 예측 물량을 매장별·사이즈별로 어떤 비율로 배분할 것인가" (정규화 분포값) |

이 두 모델의 출력을 조합하면 **매장별·사이즈별 절대 예측 수량**을 도출할 수 있으며, 이 값이 ILP의 수요 입력값이자 MD 화면의 예측 시각화 원천이 된다.

### 2.3 ② 정수 최적화 (ILP, Colly 담당)

PI팀이 운영하는 배분 최적화 서버(`POST /optimize`)에 아래 입력을 전달하면 정수 최적화로 배분 수량을 계산해 반환한다.

**입력**
- AP(논리 창고) 현재 재고 (SERP 실시간)
- 대상 매장 현재 재고 (SERP 실시간)
- 대상 매장 목록 + 매장별 우선순위(adjRank)
- 브랜드·시즌·스타일·컬러·실행일

**출력**
- 매장별·사이즈별 배분 수량(`allocQty`)

매장 우선순위(adjRank)는 배분그룹 내 매장의 상대적 배분 우선도를 나타내며, AP 창고의 가용 재고를 초과하지 않는 범위 내에서 최적 배분을 계산한다.

### 2.4 ③ 유통MD 화면 (하민 담당)

MD가 예측 시각화를 보면서 배분 대상 매장을 조정하고, AI 배분 결과를 검토·수정한 뒤 S-ERP 업로드용 엑셀 파일을 내려받는 화면이다.

**기술 스택**
- 프레임워크: Next.js 16 (React 19, TypeScript)
- UI: Tailwind CSS v4 + shadcn/ui
- 차트: Recharts
- 배포: Vercel (git push 자동 배포)
- 엑셀 생성: ExcelJS (서버사이드 API Route)

**화면 구성 — 2단계 전환 구조**

| 단계 | 화면 | 진입 조건 | 주요 기능 |
|---|---|---|---|
| 1단계 | **[화면 A] 매장 조정** | "조회하기" 클릭 | 예측 시각화 확인, 배분 대상 매장 추가/제거, 배분 시뮬레이션 실행 |
| 2단계 | **[화면 B] 피벗 상세** | "배분 시뮬레이션" 클릭 후 ILP 결과 수신 | AI 배분 결과 검토·수정, S-ERP 업로드용 엑셀 다운로드 |

> 되돌아가기는 "조회하기" 재클릭뿐(= 새 사이클 시작). 배분 결과는 엑셀 다운로드로 확정.

**[화면 A] 매장 조정 화면 상세**

1. **필터바**: 브랜드 / 시즌 / 배분그룹 / 스타일-컬러 선택
2. **스타일 네비게이터 모달**: 대분류→중분류→아이템→스타일→컬러 트리 탐색, 복수 스타일+컬러 조합 선택 가능 (각 조합이 탭으로 분리)
3. **매장 조정 테이블**: 배분 대상 매장 목록 (adjRank 순 정렬), 매장 추가(모달 검색) / 제거(X 아이콘), 조합별 탭 전환
4. **예측 시각화 3종 (MD 판단 보조)**:
   - 매장별 예측 수량 바차트 (가로축=매장, 세로축=예측 합계, adjRank 순)
   - 등급(adjRank 버킷)별 분포 요약 (그룹별 총예측·매장 수)
   - AP재고 vs 예측 총수요 게이지 ("AP에 N개, 예측 총판매 M개 → 부족/여유")

**[화면 B] 피벗 상세 화면 상세**

1. **3컬럼 피벗 테이블**: 재고 / 예측 / 배분 (ILP 결과로 배분 컬럼 자동 채워짐)
2. **매장별 보기 / 스타일별 보기 토글**
3. **엑셀 스타일 셀 편집**: Ctrl+C/V/D/R/A, 드래그, 더블클릭, Tab/화살표, Delete, F2, Ctrl+Enter 일괄입력
4. **SCS 요약 패널**: AP재고 / 배분 합계 / 잔량
5. **엑셀 다운로드**: Next.js API Route → ExcelJS → S-ERP 업로드 전용 템플릿(Case 3 물류배분) 포맷으로 생성

**외부 API 연동 최소화 전략**

| 구분 | API | 호출 시점 | 공급 방식 |
|---|---|---|---|
| SERP | `GET /warehouse-stock` | 조회하기 | 실시간 |
| SERP | `GET /shop-stock` | 조회하기 + 매장 추가 | 실시간 |
| ILP | `POST /optimize` | 배분 시뮬레이션 | 실시간 |
| Snowflake | 배분그룹 리스트 | 조회하기 | 정적 JSON (배치 아카이빙) |
| Snowflake | 매장별 SCS 예측치 | 조회하기 | 정적 JSON (배치 아카이빙) |

> 예측치와 배분그룹은 Snowflake 배치 아카이빙 JSON(`src/data/*.json`)으로 정적 공급한다. 실시간 API 호출을 3개로 최소화하여 응답 속도 및 비용 최적화, Vercel CDN 캐싱 활용.

### 5.2 화면 개발 잔여 Phase 상세

**Phase 2 — 데이터 레이어 (예상 소요: 2~3시간)**
- API Routes 6개 구현: `shop-grp`, `forecast`, `warehouse-stock`, `shop-stock`, `optimize`, `export-xlsx`
- 아카이빙 JSON 정식화: `src/data/shop_grp_archive.json`, `forecast_archive.json` → Snowflake 배치 결과로 대체
- Mock↔실 API 환경변수 스위치 연결

**Phase 3 — 상태 머신 리팩터 (예상 소요: 1~2시간)**
- `ReplenishmentTab` 컨테이너에 `phase: 'adjustment' | 'detail'` 상태 추가
- 조회하기 → [화면 A] 전환, 배분 시뮬레이션 → [화면 B] 전환 연결
- 화면 A에서 완성된 컴포넌트들을 메인 라우트에 통합

**Phase 5 — ILP 결과 반영 (예상 소요: 1~2시간)**
- `POST /optimize` 응답에서 `shopAllocations[].allocations[].allocQty` 파싱
- [화면 B] 피벗의 배분 컬럼에 ILP 결과 덮어쓰기 (예측 컬럼 유지)
- [화면 B]에서도 탭 바 유지 (조합별 ILP 결과 독립 캐싱)

**Phase 6 — 엑셀 다운로드 (예상 소요: 1~2시간)**
- `xlsx-builder.ts` 서버 유틸: ExcelJS로 `엑셀배분_템플릿.xlsx` 로드 → Case 3 (물류배분) 포맷 주입
- 파일명: `보충배분_{shopGrpNo}_{executionDate}_{ts}.xlsx`
- 전체 활성 탭의 `alloc > 0` 항목 순회 → ExportRow 배열 조립 → blob 다운로드

**Phase 7~8 — 통합 테스트 + 배포 (예상 소요: 2~3시간)**
- 해피패스 E2E: 복수 스타일 선택 → 조회 → 매장 조정 → 배분 시뮬레이션 → 엑셀 다운로드
- 에러 처리: 배분그룹 없음(404), 재고 조회 실패(500), 대상 매장 0개(422) 토스트
- Vercel Production 배포 + 환경변수 설정

## 부록. 핵심 용어 정리

| 용어 | 정의 |
|---|---|
| SC | Style-Color (스타일-컬러 조합 단위) |
| SCS | Style-Color-Size (스타일-컬러-사이즈, 최소 배분 단위) |
| AP | Allocation Party — 논리 창고 단위 (물리 창고 내 브랜드별 구역) |
| ILP | Integer Linear Programming — 정수 선형 계획법, 배분 최적화 알고리즘 |
| adjRank | 배분그룹 내 매장 우선순위 (숫자 낮을수록 우선 배분) |
| W1 | executionDate 기준 해당 주 월요일 (forecastStartDate) |
| shopGrpNo | 배분그룹 번호 — 브랜드별로 정의된 매장 묶음 |
| executionDate | 배분 실행일 (화면에 미노출, 자동 주입) |
| CP66 / CP77 | MLB 시즌 코드 (M19FCP66 / M19SCP77) |
| TFT | Temporal Fusion Transformer — SC-Total 예측 모델 (MLB용) |
| TSB | Theta-Smooth-Bootstrap — SC-Shop 분포 예측 모델 |
| LGBM | LightGBM — SC-Total 예측 모델 (DX용) |
