# 보충배분-AIA 검증 프레임워크 (Validation Framework)

> 작성일: 2026-05-19  
> 최종 수정: 2026-05-20 (데이터 범위 조정 — 운영 시간 측정 제외, 배분 품질 단일 축으로 집중)  
> 목적: 보충배분-AIA 도입 효과를 정량적으로 입증하기 위한 검증 방법론 및 지표 설계

---

## 0. 검증의 본질적 어려움 — 전제 정리

보충배분의 "정답"은 미래가 되어야 알 수 있다. MD가 100개를 배분했는데 110개가 팔렸다면 과소 배분이고, 80개가 팔렸다면 과잉 배분이다. 그런데 이 판단에는 두 가지 요인이 혼재한다.

- **판매 예측의 정확도 문제** (예측이 틀렸는가?)
- **배분 의사결정의 품질 문제** (같은 예측을 쓸 때 배분을 잘했는가?)

ILP는 예측치를 인풋으로 사용하기 때문에, 예측이 틀리면 ILP도 틀린 방향으로 최적화된다. 따라서 검증은 이 두 축을 반드시 분리해서 설계해야 한다.

### 검증 단일 축

운영 시간 측정(MD 인터뷰, 수정 이력 등)은 통제 변수가 많고 정량화가 어렵다. 검증은 **배분 품질 단일 축**으로 집중한다.

| 축 | 검증 질문 | 방법 |
|----|-----------|------|
| **배분 품질** | 같은 예측을 쓸 때, ILP의 배분 의사결정 자체가 MD보다 나은가? | 소급 시뮬레이션 (Retrospective Simulation) |

> 운영 효율성(시간 절감)은 AIA 화면의 UX 설계에서 정성적으로 언급하는 수준으로 처리한다. 시간 측정 데이터 없이 수치화하면 신뢰도가 오히려 떨어진다.

## 1. 축 1: 배분 품질 검증 — 소급 시뮬레이션

### 1-1. 기본 설계 구조

**소급 시뮬레이션(Retrospective Simulation)**이란, 과거 N주차의 데이터를 이용해 ILP를 "그 당시 상황 그대로" 돌려보는 방식이다.

어떤 주차 W에 대해 다음 세 가지를 비교한다.

```
[MD 배분 결과]    ←─┐
                    ├── 비교 대상
[ILP 배분 결과]   ←─┘

        ↓ 이후 실제 판매가 어느 쪽을 지지하는지 확인

[실제 판매 실적]
```

**필요 데이터:**

| 데이터 | 내용 | 상태 |
|--------|------|------|
| 점포별 재고 스냅샷 | 주차 시작 시점 점포 가용 재고 + 품절 시점 확인 | ✅ Snowflake 분석계 적재 |
| 창고별 가용 재고 스냅샷 | 주차 시작 시점 창고 배분 가능 재고 | ✅ Snowflake 분석계 적재 |
| 예측치 | 해당 주차 당시의 예측 수요 | ✅ `PRED_SC_W` (lgbm) / `PRED_SH_SCS_W` (tsb) |
| 실제 판매 | 배분 이후 N주간의 실제 판매량 | ✅ `DW_SCS_D` / `DW_SH_SCS_D` |
| **MD 배분 실적** | **MD가 실제로 내린 배분 결정** | **⚠️ 테이블 확인 필요 — 유일한 선결 과제** |

> ⚠️ **단 하나의 선결 과제**: MD 배분 이력 테이블명 확인. 나머지 데이터는 모두 Snowflake에서 확보 가능하다.  
> 리드타임, 배분 제약 조건, 점포 간 이동/반납 이력은 이번 검증 범위에서 제외한다.

---

### 1-2. 지표 1: 재고 소진율 (Sell-Through Rate, STR)

가장 직관적이고 비즈니스 언어로 설명하기 쉬운 지표.

```
STR = 기간 내 실제 판매량 / 배분된 재고량
```

- MD의 STR과 ILP의 STR을 비교
- **"ILP가 배분한 재고는 X%가 팔렸고, MD는 Y%가 팔렸다"** 형태로 보고

**⚠️ 단독 사용 시 함정**: STR이 100%라고 무조건 좋지 않다. 재고를 아주 적게 줬을 때도 STR이 100%가 될 수 있기 때문에, 반드시 기회손실율(LSR)과 함께 사용해야 한다.

---

### 1-3. 지표 2: 기회손실율 (Lost Sales Rate, LSR)

```
점포별 기회손실 = max(0, 실제수요 - 배분량)
전체 기회손실율 = sum(기회손실) / sum(실제수요)
```

**"실제수요"를 모르는 문제 해결 방법:**

품절이 발생하면 판매량이 0으로 기록되기 때문에 실제 수요를 직접 관측할 수 없다. 두 가지 접근으로 대응한다.

1. **예측치를 수요의 대리변수(Proxy)로 사용**: 예측치가 100인데 배분이 60이고 실제 판매도 60이면, 나머지 40은 품절로 인한 기회손실로 추정.

2. **재고 스냅샷으로 품절 시점 파악**: 별도 품절 이력 테이블 없이도, Snowflake에 적재된 재고 스냅샷에서 재고가 0이 된 주차를 찾아 품절 구간으로 확정한다. 해당 구간의 판매가 0이면서 다른 점포에서 동일 상품이 판매되고 있다면 기회손실로 간주한다.

---

### 1-4. 지표 3: 커버리지 공평성 지수 (Coverage Fairness Index)

ILP의 본질적 강점을 가장 잘 드러내는 지표. MD는 전 점포를 동시에 최적화하는 데 한계가 있어 자신에게 익숙하거나 규모가 큰 점포에 편향될 수 있다.

```
점포별 커버리지 비율 = 배분량 / 해당 점포 예측수요
커버리지 변동계수(CV) = 표준편차 / 평균
```

- **CV가 낮을수록** 모든 점포에 예측 수요 대비 균일한 비율로 배분됐다는 의미
- ILP는 수학적으로 이 균형을 목적함수로 최적화하므로, MD보다 CV가 낮게 나올 것으로 예상

**시각화 방안**: 점포별 커버리지 비율을 히스토그램으로 표현. 분포가 좁을수록(= CV 낮을수록) 공평한 배분.

---

### 1-5. 지표 4: 배분-판매 WAPE (Allocation WAPE)

배분량과 실제 판매량 간의 오차를 점포의 중요도(예측 수요 크기)로 가중 평균한 지표.

```
Allocation WAPE = sum(|배분량 - 실제판매량|) / sum(실제판매량)
```

- MD_WAPE와 ILP_WAPE 비교
- ILP가 낮다면 → 실제 판매에 더 근접한 배분을 했다는 의미

---

---

### 1-7. 핵심 분석: "MD vs ILP 다른 결정, 누가 맞았나?"

소급 시뮬레이션에서 가장 설득력 있는 케이스 스터디 소재.

**분석 방법:**

1. 전체 배분 이력에서 **MD 배분량과 ILP 추천량 간 격차가 N개 이상인 케이스**를 추출
2. 그 케이스에서 실제 판매가 어느 쪽을 지지했는지 집계
3. "격차가 큰 케이스에서의 ILP 승률" 계산

**왜 격차가 큰 케이스가 중요한가?**  
MD와 ILP가 비슷하게 배분했을 때는 어느 쪽이 맞든 의미가 작다. 크게 다른 결정을 내린 케이스에서의 승률이 ILP 알고리즘의 실질적 우위를 보여준다.

**판단 기준 예시:**

```
어떤 점포에 대해:
  MD: 30개 배분 / ILP: 50개 추천 / 실제 판매: 45개
  → ILP가 더 적절한 판단 (MD는 15개 기회손실)

  MD: 70개 배분 / ILP: 50개 추천 / 실제 판매: 48개
  → ILP가 더 적절한 판단 (MD는 22개 과잉 배분)
```

## 2. ILP가 예측이 틀려도 유리한 이론적 근거

보고에서 반드시 포함해야 할 논리. 예측 정확도와 무관하게 ILP가 MD보다 구조적으로 유리한 이유가 있다.

### 이유 1: 일관성 (Consistency)

MD는 경험과 직관이 섞이기 때문에 같은 상황에서도 날마다 다른 판단을 할 수 있다. ILP는 동일한 인풋에 대해 항상 동일한 로직으로 배분한다. 배분 프로세스의 **재현 가능성(Reproducibility)**이 보장된다.

### 이유 2: 전역 최적 (Global Optimum)

MD는 점포를 사실상 순차적으로 처리한다. 앞 순서의 점포에 재고를 많이 쓰면 뒤 순서의 점포는 부족해지는 문제가 생긴다. ILP는 **전 점포를 동시에 최적화**한다. 이것이 Global Optimum vs Local Optimum의 차이다.

### 이유 3: 다변수 동시 고려 (Multi-constraint Optimization)

MD가 직관으로 고려하기 어려운 제약들(창고별 가용 재고 총량, W1 고정 조건, 점포별 재고 잔량 등)을 ILP는 수학적으로 동시에 만족시킨다. 사람이 머릿속으로 전체 점포를 동시에 최적화하는 것은 인지적으로 불가능에 가깝다.

## 3. 보고서 검증 섹션 구성 제안

### 권장 스토리라인

```
1. 검증의 전제 및 한계 (솔직하게 먼저 인정)
   └─ 예측 정확도와 배분 품질은 별개의 문제임을 명시

2. 검증 방법론: 소급 시뮬레이션
   └─ 데이터 기간, 대상 브랜드, 분석 방법 설명
   └─ 사용 데이터: 점포/창고 재고 스냅샷 + 예측치 + 실제 판매 (모두 Snowflake 분석계)

3. 배분 품질 지표 비교 (MD vs ILP)
   ├─ STR 비교 (그래프)
   ├─ LSR 비교 — 품절 구간은 재고 스냅샷으로 확정 (그래프)
   ├─ 커버리지 공평성 분포 (히스토그램)
   └─ Allocation WAPE 비교

4. 케이스 스터디 (2~3개)
   └─ MD와 ILP가 크게 다른 결정을 내린 케이스에서 실제 판매가 어느 쪽을 지지했는지

5. 향후 검증 계획: Shadow Mode
   └─ 실제 도입 후 실시간 병행 검증으로 지속 개선 예정
```

> 💡 **한계를 먼저 인정하는 것이 오히려 신뢰도를 높인다.** "완벽하게 검증했다"는 주장보다 솔직하게 방법론의 한계를 밝히고 향후 계획을 제시하는 것이 전문성 있게 읽힌다.

## 4. 시각화 방안

| 시각화 유형 | 내용 | 적합한 차트 |
|-------------|------|-------------|
| MD vs ILP 재고 소진율 비교 | 주차별 STR 추이 | 라인 차트 (2선 비교) |

| MD vs ILP 결정 격차 분석 | 격차 크기별 ILP 승률 | 산점도 또는 버블 차트 |

## 5. Snowflake 쿼리 방향 (소급 시뮬레이션용)

```sql
-- 예측치 조회 (특정 주차, 특정 브랜드)
SELECT
    ITEM_CD,
    STORE_CD,
    WEEK,
    PRED_QTY
FROM PRED_SC_W
WHERE BRAND_CD = 'XXX'
  AND WEEK = 'YYYY-WW';

-- 실제 판매 조회 (배분 이후 N주 누적)
SELECT
    ITEM_CD,
    STORE_CD,
    SUM(SALE_QTY) AS ACTUAL_SALES
FROM DW_SCS_D
WHERE SALE_DT BETWEEN 'YYYY-MM-DD' AND 'YYYY-MM-DD'
  AND BRAND_CD = 'XXX'
GROUP BY ITEM_CD, STORE_CD;

-- 점포별 재고 스냅샷 (품절 구간 확인용 — 재고가 0인 주차를 찾는다)
-- SELECT ITEM_CD, STORE_CD, SNAP_WEEK, STOCK_QTY
-- FROM [점포_재고_스냅샷_테이블]
-- WHERE BRAND_CD = 'XXX' AND STOCK_QTY = 0

-- MD 배분 실적 조회 (테이블명 확인 필요 — 유일한 선결 과제)
-- SELECT * FROM [배분_이력_테이블]
-- WHERE BRAND_CD = 'XXX' AND DIST_WEEK = 'YYYY-WW'
```

> ⚠️ **선결 과제 단 하나**: MD 배분 이력 테이블명 확인. 점포/창고 재고 스냅샷, 예측치, 판매 실적은 모두 Snowflake 분석계에서 확보 가능하다.

## 6. 단계별 검증 로드맵

| 단계 | 시점 | 방법 | 목표 |
|------|------|------|------|
| 1단계 (현재 가능) | 보고 전 | 소급 시뮬레이션 | 이론적 비교 근거 마련 |
| 2단계 (도입 초기) | 배포 후 1~2개월 | Shadow Mode 병행 운영 | 실시간 MD vs ILP 비교 |
| 3단계 (안정화 후) | 배포 후 3~6개월 | Before/After 실적 비교 | 실질 효과 측정 및 최종 보고 |

**Shadow Mode**란, ILP를 실제 배분에 사용하지 않고 MD가 배분 결정을 내릴 때 동시에 ILP도 돌려서 결과를 기록해두는 방식이다. 이후 실제 판매 데이터로 어느 쪽이 더 나은 결정이었는지 평가한다. 가장 공정하고 신뢰도가 높은 검증 방법이다.

## 7. 한계점 정리

보고에서 솔직하게 명시해야 할 한계들.

1. **예측 불확실성**: ILP는 예측치를 인풋으로 사용하므로 예측이 틀리면 최적 배분도 틀릴 수 있다.
2. **MD의 암묵지(Tacit Knowledge)**: MD의 판단에는 현장 정보, 프로모션 계획, 행사 일정 등 데이터에 없는 정보가 반영될 수 있다.
3. **1주차 데이터 일반화 금지**: 단일 주차 결과로 전체 성능을 평가하면 결론이 흔들린다. 최소 2주, 구간별 편향을 분리해서 분석해야 한다.
4. **계절성·신상품 특수성**: 시즌 변곡점, 신상품 출시 시점은 별도 분리 분석이 필요하다.
