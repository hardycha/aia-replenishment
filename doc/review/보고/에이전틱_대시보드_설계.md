# 보충배분 AIA — 에이전틱 대시보드 설계

> 작성일: 2026-05-28  
> 배경: 이사보고(05-27) 피드백 — "LLM이 에이전틱하게 돌아가야 한다. 사용자는 확정 버튼만 누르면 되게."  
> 목표: 현재 [조회하기] 화면 전에 **AI가 자율적으로 "오늘 뭘 해야 하는지"를 알려주는 첫 화면**을 추가

---

## 1. 현재 vs 변경 후 화면 흐름

### 현재

```
[조회하기 (필터 선택)] → [화면A: 매장 조정] → [시뮬레이션] → [화면B: 피벗 상세] → [엑셀 다운로드]
```

- 사용자가 브랜드/시즌/배분그룹/스타일을 **직접 선택**해야 시작
- 어떤 SC를 보충해야 하는지는 **MD가 직접 판단**
- SERP와 차별점이 없음

### 변경 후

```
[오늘의 보충 대시보드] → [조회하기] → [화면A] → [시뮬레이션] → [화면B] → [엑셀]
 ↑ 신규 화면
 AI가 "오늘 해야 할 일"을 정렬해서 보여줌
 사용자는 카드 탭 → 확정 → 완료
```

- AI가 데이터를 사전 분석하여 **"이 SC를 보충하세요"**를 추천
- 사용자는 추천 카드를 확인하고 **[보충 실행]만 클릭**
- 추후 배치 자동화 시 사용자 없이도 실행 가능한 구조

## 2. 현재 접근 가능한 데이터 인벤토리

### A. 아카이빙 JSON (프론트 내장, 이미 사용 중)

| 파일 | 원천 | 내용 | 갱신 주기 |
|------|------|------|----------|
| `forecast_archive.json` | `ML_DIST.PRED_SH_SCS_W` | 매장×사이즈별 정규화 예측치 | 주간 (`sync_forecast.py`) |
| `shop_grp_archive.json` | `DW_SHOP_GRP` + `DW_SHOP_GRP_DTL` | 배분그룹 273개 + 매장×adjRank | 일배치 (`sync_snowflake.py`) |
| `product_tree_archive.json` | `DW_PRDT` + `DW_PRDT_SC` | 스타일×컬러 69K행, 분류체계 | 일배치 |
| `brand_shops_archive.json` | `DW_SHOP` | 브랜드별 오프라인 매장 전체 | 일배치 |
| `ssn_archive.json` | `DW_PRDT` | 시즌 목록 | 시즌 단위 |
| `category_tree_archive.json` | `DW_ITEM` | 대/중/아이템 3단 분류 | 시즌 단위 |

### B. 실시간 API (DRP API Gateway, 가동 중)

| API | 데이터 | 용도 |
|-----|--------|------|
| `GET /api-gateway/ilp/ap-stk` | 창고(AP) 사이즈별 현재고 | 창고 잔량 확인, 보충 가능 여부 판단 |
| `GET /api-gateway/ilp/shop-stk` | 매장 사이즈별 현재고 | 매장 결품 감지, 재고 건강도 |
| `POST /optimize` (Colly ILP) | 최적 배분 결과 | 보충 시뮬레이션 |

### C. Snowflake (접근 가능하나 아직 미사용)

| 테이블 | 데이터 | 에이전틱 대시보드 용도 |
|--------|--------|---------------------|
| `ML_DIST.PRED_SC_W` | SC-Total 주간 판매 예측 (PRED_SC_QTY) | 전체 수요 규모 파악 |
| `SERP.BIM_SHOP_DD_STK` | 일별 매장 판매/재고 | 전주 배분 성과 리뷰, 판매 추이 |
| `PRCS.DW_SH_SCS_DACUM` | 매장 재고 스냅샷 | 재고 건강도 점수 계산 |
| `PRCS.DW_SALE` | 판매 실적 | 배분 성과 리뷰, 예측 이상 감지 |

### D. 현재 없는 데이터 (신규 구축 필요)

| 데이터 | 용도 | 구축 방법 |
|--------|------|----------|
| **배분 확정 이력** | 전주 배분 성과 리뷰 | 엑셀 다운로드 시 DB에도 저장하는 로직 추가 |
| **예측 주차별 이력** | 예측 이상 감지 (전주 예측 vs 실판매) | `sync_forecast.py`에서 이전 주차 보존 |

## 3. 에이전틱 대시보드 — 5개 섹션 상세 설계

### 섹션 1: 긴급 결품 감지

#### 한줄 요약
> 수요지수가 높은(잘 팔리는) 매장에서 특정 사이즈 재고가 0인 SC를 감지하여 즉시 보충을 알림

#### 데이터 → 판단 → 표시 흐름

```
1. 배분그룹 순회 (shop_grp_archive.json)
   ↓
2. 각 배분그룹의 SC 목록 추출 (forecast_archive.json 키에서)
   ↓
3. 각 SC에 대해 매장 현재고 조회 (shop-stk API)
   ↓
4. 수요지수 상위 매장(adjRank 1~10) 중 사이즈 재고=0 탐지
   ↓
5. 창고 잔량 대조 (ap-stk API) → 보충 가능 여부
   ↓
6. 긴급도 점수 = 수요지수 × (결품 사이즈 수 / 전체 사이즈 수) × 창고가용률
   ↓
7. 점수 높은 순으로 카드 표시
```

#### 화면 표시

```
🔴 긴급 보충 필요 — 3건

┌──────────────────────────────────────────────────┐
│ DKAZ11061 BES (디스커버리 다운자켓 블랙)           │
│                                                    │
│ 결품 매장:                                         │
│   강남점 (adjRank 2): 사이즈 95, 100 재고 0        │
│   명동점 (adjRank 4): 사이즈 100 재고 0            │
│                                                    │
│ 창고 잔량: 95(240개) 100(310개) ✅ 충분             │
│                                                    │
│ 💬 AI: "수요지수 상위 매장에서 인기 사이즈 결품.     │
│       즉시 보충하면 이번 주 판매 기회 확보 가능"     │
│                                                    │
│                        [보충 실행 →] [상세 보기]     │
└──────────────────────────────────────────────────┘
```

#### [보충 실행] 클릭 시
- 해당 SC + 배분그룹이 자동 세팅된 상태로 [화면A]로 이동
- 또는 ILP를 사전 실행하여 바로 [화면B]로 이동 (원클릭 보충)

#### 데이터 접근 가능 여부: **✅ 현재 데이터만으로 즉시 구현 가능**

### 섹션 2: AI 추천 보충 (오늘 처리 권장)

#### 한줄 요약
> 배분그룹 단위로 "오늘 보충해야 할 SC"를 자동 선별하고, 일괄 처리 버튼 제공

#### 데이터 → 판단 → 표시 흐름

```
1. 브랜드별 배분그룹 순회
   ↓
2. 각 배분그룹 내 SC별로:
   - 전체 매장 예측 판매량 합산 (forecast)
   - 전체 매장 현재고 합산 (shop-stk)
   - 창고 가용재고 (ap-stk)
   ↓
3. 보충 필요 판단:
   - 재고 커버리지 = 현재고 합 / 주간 예측
   - 커버리지 < N주 (예: 2주) → 보충 권장
   - 결품 사이즈 비율 > 30% → 긴급 권장
   ↓
4. 배분그룹별로 보충 권장 SC를 묶어 표시
   ↓
5. (선택) ILP를 사전 실행하여 "예상 배분안" 준비
```

#### 화면 표시

```
📦 오늘 처리 권장 — 배분그룹별

┌──────────────────────────────────────────────────┐
│ 26S 아우터 (XSHGR...3546)                         │
│ 보충 권장 SC: 5건                                  │
│                                                    │
│ • DKAZ11061 BES — 커버리지 1.2주, 결품 3매장       │
│ • XJWT7341 BKS — 커버리지 1.8주, 결품 1매장        │
│ • DMDJ61046 IVS — 커버리지 0.5주, 결품 7매장       │
│ • ...2건 더                                        │
│                                                    │
│ 💬 AI: "5개 SC 모두 창고 재고 충분.                 │
│       일괄 보충 시 약 15분 소요 예상"               │
│                                                    │
│      [일괄 보충 실행 →] [개별 선택]                  │
└──────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────┐
│ 26S 이너 (XSHGR...3544)                           │
│ 보충 권장 SC: 3건                                  │
│ ...                                                │
└──────────────────────────────────────────────────┘
```

#### [일괄 보충 실행] 클릭 시
- 5개 SC에 대해 ILP를 한꺼번에 호출
- 결과를 [화면B]에 탭으로 전개
- 사용자는 결과 확인 후 [엑셀 다운로드]만 클릭

#### 데이터 접근 가능 여부: **✅ 현재 데이터만으로 구현 가능**

### 섹션 3: 전주 배분 성과 리뷰

#### 한줄 요약
> 지난주 배분한 SC의 실 판매 전환율을 보여주고, 과잉/과소 배분 매장을 식별하여 adjRank 조정을 제안

#### 데이터 → 판단 → 표시 흐름

```
1. 전주 배분 이력 로드 (배분 확정 DB — 현재 미존재)
   ↓
2. 해당 SC의 전주 매장별 실 판매 조회 (DW_SALE or BIM_SHOP_DD_STK)
   ↓
3. 매장별 판매전환율 = 실판매 / 배분수량
   ↓
4. 전체 전환율, 과잉배분 TOP N, 과소배분 TOP N 산출
   ↓
5. LLM이 패턴 분석 → adjRank 조정 제안
```

#### 화면 표시

```
📊 전주 배분 성과 (W21)

전체: 배분 12건 → 판매전환 8건 (67%)

과잉배분 TOP3:
  포항점: 배분 15 → 판매 3 (전환 20%) ⚠️
  울산점: 배분 12 → 판매 2 (전환 17%) ⚠️

과소배분 TOP3:
  강남점: 배분 5 → 판매 8 (전환 160%) → 추가 보충 필요
  명동점: 배분 3 → 판매 5 (전환 167%) → 추가 보충 필요

💬 AI: "강남점은 3주 연속 과소배분입니다.
      adjRank를 3→2로 올리는 것을 권장합니다."
      [adjRank 조정 적용] [무시]
```

#### 선결 조건
- **배분 확정 이력 DB 구축 필요** — 현재 엑셀 다운로드만 가능, DB 미저장
- **DW_SALE 아카이빙 파이프라인 추가 필요**

#### 데이터 접근 가능 여부: **❌ 신규 데이터 구축 필요**

### 섹션 4: 창고 재고 소진 임박 경고

#### 한줄 요약
> 현재 소진 속도 기준으로 N주 후 결품이 예상되는 사이즈를 경고하고, 보충 물량 조정 또는 발주 검토를 제안

#### 데이터 → 판단 → 표시 흐름

```
1. 창고(AP) 사이즈별 현재고 조회 (ap-stk API)
   ↓
2. 주간 예측 소진량 = forecast 전 매장 합산 (forecast_archive.json)
   ↓
3. 남은 주수 = 창고잔량 / 주간 예측 소진량
   ↓
4. 남은 주수 < 2주 → 경고 (노란색)
   남은 주수 < 1주 → 위험 (빨간색)
   ↓
5. "보충 물량 축소" 또는 "구매팀 추가 발주 검토" 액션 제안
```

#### 화면 표시

```
⚠️ 창고 소진 임박 — 2건

┌──────────────────────────────────────────────────┐
│ 🔴 DMDJ61046 BKS (다운자켓 블랙)                   │
│                                                    │
│ 사이즈 110: 잔량 60개 / 주간 소진 45개 → 1.3주      │
│ 사이즈 105: 잔량 80개 / 주간 소진 52개 → 1.5주      │
│ ████████████░░░ 110                                │
│ ██████████████░ 105                                │
│                                                    │
│ 💬 AI: "사이즈 110, 105가 2주 내 결품 예상.         │
│       이번 주 보충 물량을 줄이거나,                  │
│       구매팀에 추가 발주를 검토하세요."              │
│                                                    │
│           [보충 물량 조정] [발주 요청 메모]           │
└──────────────────────────────────────────────────┘
```

#### 데이터 접근 가능 여부: **✅ 현재 데이터만으로 구현 가능**
- ap-stk API + forecast_archive.json만으로 기본 계산 가능
- DW_SALE 연동 시 "실제 소진 속도" 기반으로 정밀도 향상

### 섹션 5: 예측 이상 감지

#### 한줄 요약
> 전주 예측 대비 실판매가 크게 벗어난 SC를 탐지하여, 보충 대상 긴급 격상/축소를 제안

#### 데이터 → 판단 → 표시 흐름

```
1. 전주 예측치 로드 (forecast_archive.json 이전 버전 — 현재 미보존)
   ↓
2. 전주 실 판매 조회 (DW_SALE or BIM_SHOP_DD_STK)
   ↓
3. 이상 비율 = 실판매 / 예측
   ↓
4. 이상 비율 > 150% → 예측 과소 → 보충 대상 격상
   이상 비율 < 50% → 예측 과대 → 보충 대상 축소
   ↓
5. LLM이 원인 추정 + 액션 제안
```

#### 화면 표시

```
📊 예측 이상 감지 — 1건

┌──────────────────────────────────────────────────┐
│ 🔺 DKAZ11061 BES — 전주 예측 대비 +180% 판매      │
│                                                    │
│ 예측: 25개 → 실판매: 70개                          │
│                                                    │
│ 💬 AI: "예측 대비 대폭 초과 판매. 프로모션 효과     │
│       또는 트렌드 변화 가능성. 이번 주 보충 대상을   │
│       긴급 격상하고, 창고 물량을 우선 확보하세요."   │
│                                                    │
│            [긴급 보충 격상] [원인 메모]              │
└──────────────────────────────────────────────────┘
```

#### 선결 조건

- **DW_SALE 아카이빙 파이프라인 추가 필요**

## 5. 구현 아키텍처 방안

### Option A: 배치 사전계산 (cron → JSON)

```
[매일 아침 6시]
  sync_dashboard.py 실행
    ├── shop-stk API × 전 배분그룹 호출
    ├── ap-stk API × 전 SC 호출
    ├── forecast_archive.json 로드
    └── 분석 결과 → dashboard_alerts.json 저장

[사용자 화면 진입]
  dashboard_alerts.json 즉시 표시 (로딩 0초)
```

- **장점**: 화면 로딩 즉시, LLM API 비용 없음
- **단점**: 배치 간격 동안 데이터 지연, DRP API 대량 호출 부하 확인 필요

### Option B: 온디맨드 LLM 분석 (진입 시 실시간)

```
[사용자 화면 진입]
  → 실시간으로 shop-stk/ap-stk 호출
  → LLM에게 데이터 전달 + 분석 요청
  → 10~30초 후 결과 표시
```

- **장점**: 항상 최신, 판단 근거 투명
- **단점**: 로딩 시간, LLM API 비용

### Option C: 하이브리드 (배치 + LLM 해석) — **추천**

```
[배치]
  sync_dashboard.py → dashboard_alerts.json (수치 계산)

[화면 진입]
  dashboard_alerts.json 즉시 표시 (수치 카드)
  + LLM이 자연어 해석 레이어 추가 (비동기)
  "💬 AI: 강남점은 3주 연속 결품입니다..."
```

- **장점**: 빠른 로딩 + 자연어 인사이트
- **단점**: 구현 복잡도 가장 높음

## 6. 자동화 확장 경로

```
Phase 1 (현재): MD가 대시보드 보고 [확정] 클릭
Phase 2 (단기): 배치가 대시보드 생성 + MD에게 알림 (Slack/메일)
Phase 3 (중기): MD 확인 없이 배치가 자동 배분 → 엑셀 S-ERP 업로드
Phase 4 (장기): 완전 무인 — 배치 실행 → ILP → S-ERP 자동 업로드 → 이상 시에만 MD 알림
```

각 Phase에서 **사용자 개입이 점점 줄어드는** 구조. Phase 1부터 시작하되, 코드 구조는 Phase 4까지 확장 가능하게 설계.
